# 메뉴별 정보 보강 개편 기획 (2026-11-19)

## 1. 왜 개편하는가

현재 각 메뉴는 사진과 짧은 문장으로 분위기를 전하는 데까지는 잘 되어 있다. 그러나 끝까지 읽은 환자와 보호자가 실제로 궁금해하는 것에는 답하지 못한다.

| 메뉴 | 지금 전하는 것 | 끝까지 읽어도 알 수 없는 것 |
|---|---|---|
| 입원실 | 온돌 병실, 화장실, 소독, 라운지, 찜질방의 분위기 | 병실 종류와 정원, 비치 물품, 준비물, 보호자 상주, 면회, 병실료 |
| 자연환경 | 강, 황토길, 숲길, 조깅 길의 풍경 | 길의 거리와 소요 시간, 난이도, 계절·날씨별 이용, 체력이 약할 때의 이용법 |
| 치료재활 | 통합 케어, 온열치료, 면역, 간호, 프로그램 | 누가 진료하는지, 입원 후 진행 순서, 치료별 대상과 횟수, 본원 항암 일정과의 병행 |
| 식사 | 식치 철학, 맞춤 식단, 텃밭 | 식사 시간, 식단 종류별 대상, 항암 중 입맛·소화 문제 대응, 보호자 식사 |
| 비급여 | 가격표 | 급여·비급여 구분, 실손보험 서류, 결제·정산 방식 |

개편 방향은 하나다. **기존 스토리는 그대로 두고, 그 아래에 "환자에게 도움이 되는 정보" 구간을 덧붙인다.** 위쪽은 마음을 움직이고, 아래쪽은 결정을 돕는다.

## 2. 페이지 구성 원칙: 그래픽으로 보여 주고, 글은 최소로

정보 구간은 읽는 화면이 아니라 **보는 화면**으로 만든다. 독자는 50~70대 환자와 보호자이고 대부분 휴대폰으로 본다. 긴 문단은 읽히지 않는다.

```
[기존] 히어로 → 스토리 섹션들 → 마지막 장면        ← 수정하지 않음
[신규] ── 구분 제목 한 줄 ──
        ① 아이콘 카드 (핵심 사실 4~6개)
        ② 그래픽 블록 2~3개 (도식·사진 카드·표 중 내용에 맞는 형태)
        ③ 자주 묻는 질문 (접힌 상태, 3~4개)
        ④ 다음 메뉴 (사진 카드 2장)
[기존] 공통 CTA
```

**글자 수 규칙**

| 요소 | 상한 |
|---|---|
| 구분 제목 | 한 줄, 15자 안팎 |
| 아이콘 카드 | 라벨 6자 + 값 한 줄 (예: "보호자 상주 / 1인실 가능") |
| 그래픽 블록 | 제목 한 줄 + 항목당 12자 안팎. 문단 금지 |
| 사진 카드 | 사진 + 캡션 한 줄 |
| 질문 답변 | 두 문장 이내. 평소에는 접혀 있음 |

한 화면(휴대폰 기준)에 문장이 세 줄 넘게 이어지면 그래픽으로 바꾸거나 덜어낸다. 자세한 설명이 꼭 필요한 내용은 화면에 풀지 않고 접힌 질문 안이나 전화 상담으로 넘긴다.

**그래픽 형태 6종**

| 형태 | 쓰임 | 예 |
|---|---|---|
| 아이콘 카드 격자 | 사실 나열 | 병실 시설, 식단 종류 |
| 단계 도식 | 순서가 있는 것 | 입원 절차, 치료 진행 순서 |
| 시간표 띠 | 하루·일주일 흐름 | 식사 시간, 주간 프로그램 |
| 사진 카드 | 눈으로 확인할 것 | 병실, 상차림, 산책 코스 |
| 약도·지도 | 위치와 동선 | 산책 코스 약도, 오시는 길 |
| 체크리스트 | 챙길 것 | 입원 준비물 |

- 아이콘은 지금 쓰는 선형 아이콘(lucide)으로 통일하고, 색은 브랜드 그린(`#3F6B4F`) 한 가지만 쓴다.
- 배경은 베이지(`#F7F6F3`), 카드는 흰색에 둥근 모서리 20px. 비급여 페이지와 같은 양식이다.
- 숫자는 크게, 단위는 작게 쓴다 (예: **1.2**km, **20**분).
- 모든 수치와 운영 정보는 병원이 확인한 값만 싣는다.
- 검색 노출을 위한 글은 화면 대신 사진의 대체 텍스트, 접힌 질문, 구조화 데이터에 담는다. 화면의 글자를 줄여도 검색 로봇이 읽는 정보는 유지된다.

가격표는 그대로 두고 표 아래에 도식 두 개만 붙인다.

| 실손보험 청구 | 3단계 도식 + 서류 아이콘 | 서류 요청 → 발급 → 보험사 제출 | 서류 비용은 기존, 절차 확인 |

### 3-6. 필요한 시각 자료

그래픽 중심으로 가면 글 대신 **사진과 그림이 확인 항목**이 된다.

- 병실 종류별 사진, 의료진 사진, 식단 종류별 상차림 사진, 계절별 풍경 사진
- 산책 코스 약도를 그릴 수 있는 배치도나 위성 사진 기준 동선
- 주간 식단표 원본

도식과 아이콘, 약도 그림은 제작한다. 사진이 없는 블록은 아이콘 도식으로 먼저 내보내고 사진이 오면 교체한다.

## 4. 메뉴 구성에 대한 제안

위 기획에서 "입원 절차", "오시는 길", "의료진 소개"는 특정 메뉴에 얹기에는 독립성이 큰 정보다. 두 가지 안이 있다.

- **1안 (권장): 기존 5개 메뉴 유지.** 입원 절차는 입원실에, 오시는 길은 자연환경에, 의료진은 치료재활에 넣는다. 하단 탭이 그대로라 구조 변경이 없고, 요청하신 "기존 유지 + 하단 보강"에 가장 가깝다.
- **2안: "입원안내" 메뉴 신설.** 입원 절차, 준비물, 면회, 오시는 길을 한 페이지로 모은다. 검색 유입에는 유리하지만 하단 탭이 6개로 늘고, 지난번 제거한 탭 자리를 다시 쓰게 된다.

1안으로 시작하고, 내용이 충분히 쌓이면 2안으로 분리하는 순서를 권한다.

## 5. 문구 작성 기준과 의료광고 점검

신규 구간은 정보성 문장이라 의료법 제56조(의료광고) 위반 소지가 스토리 문구보다 크다. 작성 기준은 다음과 같다.

- 치료 효과를 보장하거나 단정하지 않는다. "~에 도움을 줄 수 있습니다", "의료진 판단에 따라 시행합니다"처럼 쓴다.
- 다른 병원과 비교하거나 "최고", "유일" 같은 표현을 쓰지 않는다.
- 환자 치료 경험담과 전후 사례를 싣지 않는다.
- 비급여 치료를 소개할 때는 가격과 함께 부작용·주의사항을 같이 적는다.
- 의학 정보는 의료진·영양팀 감수를 거친 뒤 게시한다.

기획 과정에서 **기존 문구 중 점검이 필요한 표현**도 확인했다. 이번 개편 범위는 아니지만 함께 검토하기를 권한다.

| 위치 | 현재 문구 | 우려 |
|---|---|---|
| 치료재활, 고주파 온열치료 | "암세포를 선택적으로 공격하고" | 치료 효과 단정 |
| 치료재활, 고주파 온열치료 | "항암치료의 효율성을 높인다는 논문들이 발표되고 있습니다" | 출처 없는 근거 인용 |
| 치료재활, 편백나무 찜질방 | "피부 미용에 탁월한 효과가 있습니다" | 효과 단정 |
| 치료재활, 마지막 장면 | "치유를 완성하는 병원입니다" | 결과 보장으로 읽힐 여지 |
| 치료재활, 멘토링 | "같은 질병을 극복한 선배 환자의 생생한 경험" | 치료 경험담 활용 여부 확인 필요 |

## 6. 검색 노출 효과

- 화면의 글은 적지만, 사진 대체 텍스트와 접힌 질문, 구조화 데이터에 "입원 준비물", "항암 중 식사"처럼 환자가 실제로 검색하는 내용이 담긴다.
- 메뉴별 자주 묻는 질문은 FAQ 구조화 데이터로 함께 내보낸다. 지금은 랜딩에만 있다.
- 주소·전화·진료 정보가 본문 텍스트로 들어가 지역 검색(춘천 요양병원)에 유리해진다.
- 메뉴 간 "다음에 볼 메뉴" 링크로 내부 연결이 촘촘해진다.

## 7. 구현 방식

- 신규 구간의 내용은 화면 코드와 분리해 `src/app/data/` 아래 메뉴별 데이터 파일로 둔다. 병원 정보가 바뀌면 데이터 파일만 고치면 된다.
- 그래픽 부품 6종(아이콘 카드, 단계 도식, 시간표 띠, 사진 카드, 약도, 체크리스트)과 접이식 질문, 다음 메뉴 카드를 공통 부품으로 만든다. 도식은 이미지 파일이 아니라 코드로 그려 글자가 선명하고 수정이 쉽게 한다.
- 메뉴별 질문은 `seo.ts`에 연결해 페이지별 FAQ 구조화 데이터를 자동 생성한다.
- 기존 스토리 섹션의 코드는 건드리지 않고, 각 페이지에서 `<CTASection />` 바로 위에 신규 구간 하나만 끼운다.

## 8. 지도를 카카오맵으로 교체

지금은 모든 페이지 하단(공통 CTA)에 구글 지도가 들어 있다. 국내 환자와 보호자는 카카오맵과 카카오내비를 주로 쓰므로 카카오맵으로 바꾼다.

**화면 구성**

- 지도 영역: 병원 위치에 마커가 찍힌 카카오맵
- 지도 아래 버튼 2개: "카카오맵에서 보기"(장소 상세 페이지), "길찾기"(도착지가 병원으로 지정된 화면)
- 주소 텍스트와 "주소 복사" 버튼
- 자연환경 메뉴의 "오시는 길" 블록에서는 같은 지도를 크게 쓰고 교통 안내를 붙인다

**연결 방식 비교**

| 방식 | 필요한 것 | 장점 | 단점 |
|---|---|---|---|
| A. 지도 퍼가기 (권장) | 카카오맵에서 병원을 검색해 "지도 퍼가기"로 발급받는 코드 | 가입·키 없이 가능, 병원 장소 정보와 연결 | 지도 모양 조정 폭이 좁음 |
| B. 카카오맵 API | 카카오 개발자 계정의 앱 키, 사이트 도메인 등록 | 마커·확대 수준 등 자유롭게 조정 | 키 발급과 도메인 등록 필요, 일일 호출 한도 관리 |
| C. 정적 지도 이미지 + 링크 | 병원 좌표 | 가장 가볍고 빠름 | 지도를 움직일 수 없음 |

A안으로 시작한다. 지도는 화면에 보일 때만 불러오도록 해서 페이지 속도에 영향을 주지 않게 한다.

**필요한 정보**

- 카카오맵에 등록된 병원 장소 주소(place URL) 또는 장소 ID
- A안이면 "지도 퍼가기" 코드, B안이면 앱 키
- 카카오맵에 병원 정보(전화, 진료시간, 사진)가 최신인지 확인. 지도에서 넘어간 사람이 보는 첫 화면이다

## 9. 진행 순서

| 단계 | 내용 | 담당 |
|---|---|---|
| 1 | 이 기획 확정 (메뉴 구성 1안/2안, 블록 가감) | 대표 |
| 2 | 병원 확인 항목 수집. 아래 10절 질문지 사용 | 병원 |
| 3 | 공통 부품과 데이터 구조 제작, 기존 정보만으로 채울 수 있는 블록 먼저 게시 | 개발 |
| 4 | 확인된 정보로 메뉴별 문구 작성, 의료진·영양팀 감수 | 개발 + 병원 |
| 5 | 의료광고 표현 점검 후 게시, 사이트맵 재제출 | 개발 |

지도 교체(8절)는 메뉴 개편과 독립된 작업이라 필요한 정보만 받으면 먼저 진행할 수 있다.

3단계는 병원 답변을 기다리지 않고 바로 시작할 수 있다. 아이콘 카드와 텃밭 도식, 일부 질문은 이미 사이트에 있는 사실만으로 채워진다.

## 11. 구현 현황 (2026-11-19, 1차)

이미 사이트에 공개된 사실만으로 만들 수 있는 블록을 먼저 구현했다. 코드는 `src/app/components/info/`에 있다.

| 메뉴 | 구현한 블록 | 병원 확인 후 추가할 블록 |
|---|---|---|
| 입원실 | 병실과 시설 아이콘 6개, 1인실 병실료, 보호자 안내, 질문 3개 | 병실 비교 사진, 입원 절차, 준비물, 면회 |
| 자연환경 | 걷는 길 사진 카드 4장, 하루의 흐름 도식, 질문 2개 | 코스 약도와 거리·시간, 체력별 추천, 사계절, 교통 안내 |
| 치료재활 | 치료와 관리 아이콘 6개, 살피는 증상 4개, 주요 비급여 비용, 질문 4개 | 진행 순서, 의료진, 24시간 대응 도식, 주간 프로그램 |
| 식사 | 맞춤 식단 4종, 텃밭에서 식탁까지 도식, 상차림 사진 2장, 질문 2개 | 식사 시간표, 증상별 조정, 주간 식단표 |
| 비급여 | 급여·비급여 대비 도식, 진행 방식 도식, 질문 2개 | 실손보험 청구 절차 |

- 모든 메뉴 끝에 "함께 보면 좋습니다" 카드 2장을 넣었다.
- 공통 CTA의 구글 지도를 카카오맵 연결 카드로 바꿨다. 카카오맵 장소 상세와 길찾기로 이동하고, 주소 복사 버튼이 있다. 화면 안에 움직이는 카카오 지도를 넣으려면 "지도 퍼가기" 코드나 API 키가 필요하다.
- 질문은 랜딩의 자주 묻는 질문에서 메뉴와 관련된 것만 골라 쓴다. 메뉴 전용 질문은 병원 확인 후 추가한다.
- 블록을 추가하려면 `MenuInfo.tsx`의 해당 메뉴에 부품 한 줄을 넣으면 된다.

## 12. 표현 원칙 변경 (2026-11-19, 2차)

아이콘 도식은 쓰지 않는다. 정보 블록은 **실제 사진 썸네일**을 기본으로 한다. 2절의 "그래픽 형태 6종"과 3절 표의 "아이콘 카드", "단계 도식"은 아래 형태로 바꿔 읽는다.

| 형태 | 쓰임 |
|---|---|
| 썸네일 카드 | 사진 + 라벨 한 줄. 시설, 치료, 코스, 상차림 |
| 순서 썸네일 | 사진 위에 "아침", "오후" 같은 짧은 표시를 얹어 흐름을 보여 줌 |
| 금액 카드 | 숫자는 크게, 단위는 작게 |
| 글자 태그 | 맞는 사진이 없는 짧은 항목 (식단 종류, 살피는 증상 등) |
| 번호 단계 | 사진으로 표현할 수 없는 절차 |

- 맞는 사진이 없으면 아이콘으로 대체하지 않는다. 글자 태그로 두고, 필요한 사진을 병원 요청 목록에 올린다.
- 사진은 내용을 직접 확인하고 배치한다. 기존 코드의 사진 설명 중 실제 장면과 다른 것이 있었다(간호 스테이션으로 적힌 단체 체조 사진, 찜질방으로 적힌 테라스 사진 등).
- 추가로 받으면 좋은 사진: 면역 주사요법 장면, 식단 종류별(저염식·영양죽 등) 상차림, 간호 스테이션, 저녁 시간대 병원 풍경.

## 13. 운동 코스 지도 개편 (2026-11-19)

자연환경 메뉴의 코스 지도(말풍선이 그려진 위성사진 한 장)를 움직이는 지도로 바꿨다.

- **바탕**: 기존 지도의 위성사진을 그대로 쓴다. 말풍선·선·핀만 지웠고, 지운 자리만 Higgsfield(GPT Image)로 채운 뒤 원본에 합성했다. 그 밖의 강·숲·길은 원본 픽셀 그대로다. 원본은 `assets-original/course-map-base.png`.
- **코스 선**: 기존 지도의 선에서 좌표를 추출해 코드로 그린다(`src/app/data/courseMap.ts`). 공개 지도(OpenStreetMap)의 도로와 겹쳐 위치가 맞는지 확인했다.
- **움직임**: 화면에 들어오면 세 코스가 그려지고, 코스를 누르면 그 길만 강조되며 점이 길을 따라 움직인다. 왕복 코스는 갔다가 돌아오고, 동산길은 한 바퀴 돈다. 병원 위치는 물결처럼 퍼지는 표시로 보여 준다.
- **표시 정보**: 기존 지도에 있던 관천리길 왕복 1시간, 동산길 40분 코스만 쓴다. 다산 정약용길은 소요 시간 안내가 없어 이름만 표시한다.
- 지도에서 잰 길이는 관천리길 편도 약 2.3km, 동산길 한 바퀴 약 2.5km, 다산 정약용길 표시 구간 약 1.3km다. 추정값이라 화면에는 넣지 않았다. 병원 확인 후 추가할 수 있다.
- 바탕 위성사진은 병원이 쓰던 지도 이미지에서 온 것이라 원 출처(지도 서비스)의 이용 조건 확인이 필요하다.
