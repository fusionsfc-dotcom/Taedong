# 온라인 문의 기능 및 비급여 노출 정리 기획 (2026-11-19)

## 1. 목표

- 환자와 보호자가 **휴대폰 번호와 질문만 남기면** 병원이 문자로 답하거나, 원하면 전화를 걸어 주는 문의 창구를 만든다.
- 전화 걸기를 망설이는 사람도 30초 안에 문의를 끝낼 수 있게 한다.
- 비급여 가격 정보는 비급여 메뉴에서만 보이게 한다.

지금 사이트의 행동 유도는 "전화 상담하기" 버튼 하나다. 전화는 진료 시간에만 가능하고, 낯선 병원에 바로 전화하는 것을 부담스러워하는 사람이 많다. 문의 창구는 이 사람들을 놓치지 않기 위한 것이다.

## 2. 퍼널 설계

문의를 한 화면의 긴 양식으로 받지 않는다. 한 번에 하나씩, 누르기만 하면 넘어가는 세 단계로 나눈다. 앞 단계에서 작은 선택을 한 사람은 끝까지 갈 가능성이 높다.

```
[진입]  어느 페이지에서든 "문의하기" 버튼
   ↓
[1단계] 무엇이 궁금하세요?        ← 누르기만 함 (입력 없음)
   ↓
[2단계] 어떻게 답해 드릴까요?      ← 문자 / 전화 중 선택
   ↓
[3단계] 휴대폰 번호 + 질문(선택)   ← 입력은 여기 한 번뿐
   ↓
[완료]  접수 확인 + 다음 안내
```

### 단계별 구성

| 단계 | 화면에 보이는 것 | 입력 방식 | 마찰을 줄이는 장치 |
|---|---|---|---|
| 1. 주제 | "무엇이 궁금하세요?" 주제 버튼 5~6개 | 한 번 누르면 바로 다음 단계 | 보고 있던 메뉴의 주제가 맨 앞에 미리 표시됨 |
| 2. 답변 방법 | "문자로 받기" / "전화로 받기" | 한 번 누름. 전화를 고르면 희망 시간대 3개 중 선택 | 문자를 기본 추천으로 표시 |
| 3. 연락처 | 휴대폰 번호, 질문(선택), 동의 한 줄 | 숫자 키패드 자동 표시, 하이픈 자동 입력 | 질문은 비워도 접수됨. 1단계 주제가 질문을 대신함 |
| 완료 | "접수됐습니다" + 답변 예상 시점 | 없음 | 기다리는 동안 볼 메뉴 2개를 사진 카드로 제시 |

- 상단에 진행 표시(점 3개)를 두어 얼마 남았는지 보여 준다.
- 뒤로 가기를 눌러도 앞에서 고른 내용이 남아 있다.
- 글자는 본문 18px 이상, 버튼 높이 60px 이상으로 한다. 독자는 50~70대다.

### 1단계 주제 (안)

입원 상담, 입원실·시설, 치료·재활, 식사, 비용, 기타.
"비용"을 고른 사람에게는 완료 화면에서 비급여 메뉴를 안내한다.

### 진입 지점

| 위치 | 형태 | 미리 선택되는 주제 |
|---|---|---|
| 모든 페이지 하단 탭 | 가운데 강조 버튼 "문의" | 현재 메뉴에 맞춤 |
| 공통 CTA | "전화 상담하기" 위에 "문자로 문의하기"를 주 버튼으로 | 현재 메뉴에 맞춤 |
| 메뉴별 정보 구간 끝 | "이 내용이 궁금하세요? 문의하기" 한 줄 버튼 | 해당 메뉴 |
| 랜딩 자주 묻는 질문 아래 | "찾는 답이 없으신가요?" | 기타 |

문의 창은 새 페이지로 이동하지 않고 화면 아래에서 올라오는 창으로 연다. 보던 내용을 잃지 않는다.

### 완료 이후

- 접수 즉시 문의자에게 확인 문자를 보낸다. (예: "[춘천태동요양병원] 문의가 접수됐습니다. 진료 시간 안에 답변드리겠습니다.")
- 병원 담당자에게 알림 문자를 보낸다. 주제, 답변 방법, 희망 시간, 번호, 질문이 담긴다.
- 답변 예상 시점은 병원이 지킬 수 있는 값만 적는다. (병원 확인 필요)

## 3. 접수와 답변 흐름

홈페이지는 지금 서버가 없는 정적 사이트다. 문의를 받으려면 작은 서버 기능이 필요하다.

```
방문자 → 문의 창 → 서버 함수(Vercel) ─┬→ 병원 담당자 휴대폰: 알림 문자
                                      ├→ 문의자 휴대폰: 접수 확인 문자
                                      └→ 문의 기록 저장 (시트 또는 DB)
병원 담당자 → 문자 답장 또는 전화 걸기
```

| 구성 요소 | 방안 | 비고 |
|---|---|---|
| 서버 함수 | Vercel 서버리스 함수 | 지금 호스팅에 그대로 추가 가능 |
| 문자 발송 | 국내 문자 발송 서비스(솔라피, 알리고, NHN 등) | 발신번호 사전 등록 필수. 건당 수십 원 |
| 기록 저장 | 구글 시트 또는 간단한 DB | 누락 방지와 응대 현황 관리용 |
| 스팸 방지 | 같은 번호·IP의 연속 접수 제한, 숨은 입력란 | 화면에 문자 인증은 넣지 않는다. 단계가 늘어나기 때문 |

**전화 답변**은 자동 연결 장치 없이 시작한다. 담당자가 알림 문자를 보고 희망 시간대에 직접 전화를 건다. 문의가 많아지면 자동 콜백 연결(클릭 투 콜)을 검토한다.

## 4. 개인정보와 의료 관련 유의사항

- **수집 항목 최소화**: 휴대폰 번호만 필수. 이름도 받지 않는다.
- **동의**: 3단계에서 수집 항목, 이용 목적(문의 답변), 보유 기간을 한 줄로 알리고 동의를 받는다. 전문은 눌러서 펼쳐 보게 한다.
- **건강 정보**: 병명, 병기 같은 내용은 민감정보다. 질문란에 "병명 등 건강 정보는 적지 않으셔도 됩니다"라고 안내하고, 주제 버튼으로 대부분의 문의가 해결되게 한다.
- **보유 기간**: 답변 완료 후 정해진 기간이 지나면 삭제한다. (기간은 병원 확인)
- **광고 문자 금지**: 받은 번호는 문의 답변에만 쓴다. 홍보 문자를 보내려면 별도 수신 동의가 필요하다.
- **개인정보 처리방침**: 사이트에 처리방침 페이지가 없다. 문의 기능과 함께 추가해야 한다.
- **상담 범위**: 온라인 문의는 입원·시설·비용 안내에 한정한다. 진단이나 치료 판단은 내원 상담으로 안내한다는 문구를 완료 화면에 둔다.

## 5. 비급여 내용 노출 정리

원칙: **가격과 비급여 항목은 비급여 메뉴(`/non-reimbursable`)에서만 보인다.** 다른 페이지에는 금액이 나오지 않는다.

| 위치 | 지금 | 변경 |
|---|---|---|
| 입원실 정보 구간 | "병실 비용" 카드: 1인실 150,000원 / 1일 | 삭제 |
| 치료재활 정보 구간 | "주요 비급여 비용" 카드: 온열치료, 도수치료, Pain Scrambler 금액 | 삭제 |
| 입원실·치료재활 정보 구간 | "비급여 안내 전체 보기" 링크 | 금액 카드와 함께 삭제 |
| 접이식 질문 "비용은 어느 정도입니까?" | 금액 없이 "상담을 통해 안내" | 유지. 금액이 없다 |
| 하단 탭 "비급여", CTA 메뉴 "비급여 안내" | 메뉴 이동 | 유지. 비급여 메뉴로 가는 길이다 |
| 비급여 메뉴 | 가격표 전체 | 유지 |
| 검색용 설명 문구 | 비급여 페이지 설명에만 항목 언급 | 유지 |

비용이 궁금한 방문자는 두 길로 안내한다. 하단 탭의 비급여 메뉴, 그리고 문의 창의 "비용" 주제다.

## 6. 측정

퍼널이 실제로 작동하는지 보려면 단계별 수치가 필요하다.

- 문의 창 열림 → 1단계 완료 → 2단계 완료 → 접수 완료의 인원
- 진입 지점별, 메뉴별 접수 건수
- 문자와 전화 선택 비율
- 접수부터 첫 답변까지 걸린 시간 (병원 기록)

분석 도구(구글 애널리틱스 또는 네이버 애널리틱스)를 함께 연결한다. 개인정보는 분석 도구로 보내지 않는다.

## 7. 구현 범위와 순서

| 단계 | 내용 | 병원 결정 필요 여부 |
|---|---|---|
| 1 | 비급여 노출 정리 (금액 카드 삭제) | 불필요. 바로 가능 |
| 2 | 문의 창 화면과 진입 버튼 | 불필요. 화면 먼저 제작 가능 |
| 3 | 개인정보 처리방침 페이지 | 처리방침 내용 확인 필요 |
| 4 | 서버 함수, 문자 발송, 기록 저장 | 아래 결정 사항 필요 |
| 5 | 분석 도구 연결, 실제 접수 시험 | |

2단계까지는 병원 답변 없이 만들 수 있다. 다만 4단계가 끝나기 전에는 접수 버튼을 실제로 열지 않는다. 접수됐다고 표시하고 아무에게도 전달되지 않는 상태를 피하기 위해서다.

## 8. 결정이 필요한 사항

1. **알림을 받을 담당자 번호**와 부재 시 대체 번호
2. **문자 발송 서비스**와 발신번호. 대표번호(1522-0288)로 보내려면 발신번호 등록 서류가 필요하다
3. **답변 가능 시간**과 완료 화면에 적을 답변 예상 시점. 야간·주말 접수분의 처리 방식
4. **전화 희망 시간대** 구분 (안: 오전 / 오후 / 저녁)
5. **문의 기록 보관 위치와 보유 기간**
6. **개인정보 처리방침** 내용과 개인정보 보호책임자
7. 1단계 **주제 목록** 확정

## 9. 구현 현황 (2026-11-19, 1차)

- **비급여 노출 정리 완료**: 입원실과 치료재활 정보 구간의 금액 카드를 삭제했다. 금액은 비급여 메뉴에서만 나온다.
- **문의 창 화면 완료**: 주제 → 답변 방법 → 휴대폰 번호의 세 단계. 코드는 `src/app/components/inquiry/`, 설정은 `src/app/data/inquiry.ts`.
- **진입 버튼**: 하단 탭 가운데 "문의", 공통 CTA의 "문자로 문의하기", 메뉴별 정보 구간 끝의 "궁금한 점 문의하기".
- **서버 함수 뼈대**: `api/inquiry.js`. 입력 확인과 자동 프로그램 차단까지 들어 있고, 문자 발송 부분(`sendSms`)은 비어 있다.
- **아직 꺼져 있음**: `VITE_INQUIRY_ENABLED`가 `true`가 아니면 문의 버튼이 화면에 나오지 않는다. 운영 환경에는 이 값을 넣지 않았으므로 배포해도 방문자에게 보이지 않는다.
- **로컬 확인 방법**: `.env.local`에 `VITE_INQUIRY_ENABLED=true`, `VITE_INQUIRY_MOCK=true`를 넣으면 실제 전송 없이 화면 흐름을 볼 수 있다. 완료 화면에 시험 모드 표시가 나온다.

켜기 전에 남은 일: 8절의 결정 사항, `sendSms` 연결, 개인정보 처리방침 페이지, 실제 접수 시험.

## 10. 변경 사항 (2026-11-19, 2차)

- **병원 알림을 메일로 변경**: 문자 대신 메일로 문의를 받는다. 받는 주소는 Vercel 환경 변수 `INQUIRY_EMAIL_TO`에 등록했다(저장소에는 없음). 메일에는 주제, 답변 방법, 휴대폰 번호, 질문, 보던 페이지, 접수 시각과 함께 전화 걸기·문자 보내기 링크가 들어간다.
- **메일 발송 서비스**: Resend를 쓴다. `RESEND_API_KEY`가 아직 없어 발송은 되지 않는다. 받는 주소와 같은 메일로 Resend에 가입하면 도메인 인증 없이 바로 보낼 수 있다.
- **방문자 접수 확인 문자는 보류**: 문자 서비스가 정해질 때까지 화면의 "접수됐습니다" 안내로 대신한다.
- **진입 버튼 위치 변경**: 하단 탭의 "문의"를 없애고 상단 홈 버튼 옆으로 옮겼다. 상단 바가 없는 홈에서는 오른쪽 위에 같은 버튼만 띄운다.

켜는 순서: ① Resend 가입 후 API 키를 Vercel 환경 변수 `RESEND_API_KEY`에 등록 → ② 시험 접수로 메일 수신 확인 → ③ 개인정보 처리방침 페이지 추가 → ④ `VITE_INQUIRY_ENABLED=true` 등록 후 재배포.
